# Data format

Provide three fixed split CSV files with unique `trace_name` values and corresponding HDF5 inputs. Each waveform is keyed by trace name in `/data` (the student and cache loaders also accept a flat root group). Trace names must be disjoint between splits. Store 6000 samples at 100 Hz in E, N, Z order. The EQT release loader accepts time-major `[6000,3]` and channel-major `[3,6000]` input. The release sample uses float32 time-major waveforms and retains raw amplitudes. Teacher and student apply per-component standardisation with a standard-deviation epsilon of 1e-6. Student input is then right-padded.

Place `p_arrival_sample`, `s_arrival_sample` and `trace_category` on the HDF5 trace as attributes. Arrivals are zero-based sample indices. Use `-1` for unavailable picks. `noise` traces with P/S absent are assigned background targets. An earthquake requires a valid P, and an unavailable S creates no S target. Carry matching picks, category and event ID in CSV for readable provenance. The SHA-checked cache keeps row indices and names so a reordered or mismatched split can be detected.

The train/validation cache has HDF5 shards with `p_probability` `[N,6000]` and `feature` `[N,750,32]` in their respective families, with float32 storage, trace name, CSV row index, peaks, and manual-label metadata. Each family has a manifest. The cache verifies the CSV and shard hashes. The source waveform is referenced by its resolved HDF5 path. Keep an immutable HDF5 snapshot for each cache and generate a fresh cache after any waveform or label update, even when the path and trace names stay the same. The cache manifests store resolved local paths, so regenerate after moving the inputs.
